# Contributing

The most valuable contribution is a **correction to one document**: its official URL, document
number, date or status. Open one issue per document using the "Document correction" template.

## How the data is organised

- `graph.json` is generated by `build.py`. **Edit `build.py`, not `graph.json`.**
- Every document has `domain`, `gate_from`/`gate_to`, a unique `key`, optional `group`, `triggers`,
  `verification` and `last_checked`. See README for their meaning.
- `index.html` (the page) and `figure1.svg` are generated by `build_page.py` from `graph.json`; the renderer
  holds no layout facts, so a placement change is a data change. Built-in filter presets live in `build_page.py`
  (`PRESETS`), the About texts too; `python build_page.py --internal` adds the maintainers' changelog, audit,
  roadmap and open items as `index-internal.html`.

## Workflow

1. Fork, branch, edit `build.py` (add a `node(...)`, an `upd(...)` or an `edge(...)`).
2. `python build.py && python validate.py graph.json` — must print `OK`.
3. `python build_page.py` to regenerate the page; open `index.html` locally (the Explore view needs network access to cdnjs for d3; Map and Register do not).
4. Pull request with the official source you checked, the date you checked it, and whether you opened
   the page (`verification: page`) or only located it (`search`).

Node ids and keys are stable: never rename, add instead. A superseded document stays in the graph with
`status: superseded` and a `supersedes` edge from its replacement.

## Verification levels

`page` — official page or PDF opened · `search` — URL located on the issuing body's domain ·
`secondary` — non-official source opened because the primary text was unreachable · `knowledge` —
not checked live (not acceptable for new entries).
